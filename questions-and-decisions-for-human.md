# Questions and decisions for human review

## Scope

- Implement `design.md`, completing the non-query work first. The human subsequently authorized the query engine and reuse of `../main` (see the scope updates below).
- Keep the mainline runtime and its bindings unchanged. The C implementation lives in `lib/squat/`; a separate Rust crate builds and wraps it.
- The existing untracked `todo.md` belongs to the human and is left untouched.

## Decisions

- Start with the representation and a differential testable API, then build corpus and benchmark tooling on that API.
- Version 1 uses native endianness and the exact matching grammar. Cross-endian persistence and a durable grammar fingerprint remain open design questions. The slab header is explicitly padded to 32 bytes, with all padding initialized to zero.
- Dictionary overflow is a reported conversion error, rather than the crash provisionally described in the design. Allocation and 32-bit layout overflow are reported as errors too.
- Navigation may scan siblings or ancestors when the format has no direct index. Cursors maintain an ancestor stack for efficient repeated tree walks.

## Questions

- What grammar identity should a persistent envelope record: generated parser hash, grammar source revision, or both? Version 1 callers must provide the exact matching grammar.
- Should the supertype dictionary grow beyond 256 entries by widening its node column in a later representation version?
- Should packed trees preserve included ranges as a separate optional section? The current design preserves node coordinates, but has no included-range section.

### C runtime baseline

- Implemented aligned slab columns, checked 32-bit layout arithmetic, lane-aware growth/compaction, reverse raw-subtree traversal, navigation/cursors, symbol presence entries, supertype dictionaries, and validated deserialization.
- Reverse traversal stages each open parent's child positions. Subtracting a multiline child's point extent cannot recover its preceding column. This avoids repeated forward rescanning and does not stage a full array of visible node attributes.
- Supertype bit order is ascending raw grammar ID, including metadata on ABI-14 grammars whose public supertype enumeration is unavailable. A visible node receives its incoming mask, as specified in the design; its own bit applies to children.

### Runtime column pointers and persistent metadata

- Per-column offsets are already reconstructed into the nonpersistent `SQTree.layout`. With the exact grammar and layout version known, a proposed 16-byte persisted header can retain only version/features, live group count, actual allocated group capacity, and tree-specific supertype dictionary count. A presence flag replaces the optional symbol-index offset. All section offsets and lengths are derived. Capacity is the final allocation size, not the initial estimate; it can only be omitted if persistence always compacts first.
- Runtime pointers and coallocating a prefix are separate choices. Replacing offset arrays adds 92 B with points or 60 B without on x86-64, before object padding; retaining both adds 184/120 B. A prefix can reduce allocation count, but moving it during growth would invalidate exposed node handles. Rebuild pointers after relocation/load and refresh active-index bias when group counts change. Packed ID lanes can begin mid-word, so pointers alone cannot absorb every suffix-index adjustment.
- Completed a direct-descriptor addressing probe on 20 original files (11 bounded grammar representatives and nine large files), both point modes, all raw columns validated, 12 balanced repetitions of four variants in preorder and shuffled order. Pointer-only ordinary getters are essentially tied with offsets; sequential bulk-byte reads improve about 8–9%, and all-column reads about 2–6%. These are local microbenchmarks, not query/iterator speedups.
- Caching the active group/slot bias while retaining offsets improves the individual getter probe about 9%. A single cached group bias may fit the current descriptor's four bytes of tail padding. Measure that production variant first; the probe caches two biases. Gains are not additive, and some broader kernels regress, so a pointer-table default needs whole-walk/query and many-small-tree benchmarks.
- The 16-byte header and combined allocation remain proposals. The current implementation/format is preserved while the experiment and rationale are recorded in `lib/squat/experiments/column-addressing-results-2026-09-10.{md,json}`. No user decision is required to complete this consideration; format compatibility policy would be a subsequent implementation choice.
